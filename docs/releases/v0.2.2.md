# tokn v0.2.2

This release moves gateway serving to the v2 runtime while retaining in-memory
loading of v1 configuration. It also completes the profile-based configuration
model, adds dynamic model routing and OpenCode Go support, and hardens request
persistence, credential refresh, proxy handling, and shutdown.

## Highlights

- V1 configurations run through the v2 runtime without rewriting the source
  file, including `serve --with-proxy`. `config migrate-v2` previews native v2
  configuration with compact, two-space-indented output; `--expanded` shows the
  explicit form.
- Profiles own account pools, API path mounts, and enabled endpoints. Routes
  select routing behavior and restrict providers. Profiles are available to all
  API listeners, with a default mount of `/{profile}/v1` (`/v1` for `default`).
- V2 supports provider presets, account-free relay destinations, managed routing,
  direct HTTP proxying, intercepted HTTPS, and CONNECT policies.
- Discovery, retry policies, CORS, logging, and session TTL behavior are carried
  through the v2 runtime. Model-specific reasoning-effort metadata is normalized
  for supported providers.
- Live config reload replaces a complete runtime generation. Reload authorization
  is separate from client API authentication; listener changes that require a
  restart are rejected without replacing the running configuration.
- Request records retain inbound method, URL, context, and latency. Proxy traffic
  preserves provider/account identity; unrecognized provider hosts use bare host
  names. Unsupported WebSocket upgrades are rejected before forwarding.
- Safe request-database pruning and improved nested inline TOML editing round out
  the CLI maintenance tools.
- Model discovery combines provider `/v1/models` responses with models.dev data
  instead of treating the bundled catalogue as the only source. Explicit concrete
  model IDs remain routable while discovery refreshes periodically.
- Per-model provider scores select the highest-scoring eligible account without
  requiring a complete provider list. Exact model rules and wildcard prefixes
  such as `gpt-*` can be loaded from ordinary configuration fragments.
- Codex OAuth credentials refresh through the provider flow and expose current
  usage information. Upstream errors preserve useful non-JSON response details.
- OpenCode Go is available as a provider with API-key login, quota reporting, and
  model-specific Chat Completions, Responses, and Messages routing.
- The Docker agent-test harness runs OpenCode, Pi, DSH, Codex, and Claude Code in
  isolated containers. It verifies exact text responses, real fixture reads,
  endpoint-specific event streams, and persisted request history.
- Interrupted upstream streams now retain their failure state and must contain
  the endpoint's terminal event. Abrupt peer disconnects are logged as benign
  connection closes instead of proxy failures.
- The source repository has moved to `tokn-ai/tokn`; package metadata and release
  links now point to the new GitHub organization.

## Upgrade notes

- Existing v1 configuration remains loadable. Back up configuration and database
  files before upgrading, and review migration output before adopting native v2.
- Earlier experimental v2 layouts are not supported. Regenerate from v1 or update
  them to the profile-owned pool/mount model; standalone API bindings and the old
  route-owned account pools have been removed.
- Agent link/sync settings are not part of native v2 core configuration. Agent
  tooling is being separated into `tokn-router-agent`.
- The Docker image now runs `serve` without overriding listener addresses or
  authentication. Mount a ready configuration, require client keys, and publish
  plaintext ports only on host loopback. Use a TLS reverse proxy for remote access.
  See [Docker setup](https://github.com/tokn-ai/tokn/blob/v0.2.2/docs/docker.md).
- Allow a 40-second supervisor stop timeout. SIGINT/SIGTERM stops admission,
  drains active decoded HTTP responses for up to 30 seconds, then allows five
  seconds for persistence cleanup and one second for runtime teardown. Opaque
  CONNECT tunnels close immediately; a timeout exits nonzero and may leave queued
  records incomplete.

## Downloads

The GitHub release workflow builds the CLI for Linux x86_64, macOS Apple Silicon
(aarch64), and Windows x86_64. The macOS archive name now reflects the architecture
actually built. Python/npm registry publication is not part of this CLI release;
the TypeScript SDK remains private and available from a source checkout.
